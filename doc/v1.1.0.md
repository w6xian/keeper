## 一、sloth v3 → v4 + 通信改 TCP

| 位置 | 改动 |
|---|---|
| `go.mod` / `vendor/` | `sloth/v3 v3.1.4` → `sloth/v4 v4.0.0`，`go mod tidy` + `go mod vendor` 同步 |
| `door.go` | `Listen(ctx, sloth.TCP, addr)`；移除 `mux.Router` 与 `WithUriPath`（TCP 无 HTTP 路由，且 `WithRouter` 会 `http.Handle` 重复注册直接 panic）；`Close()` 关闭 listener |
| `dog.go` | `Dial(ctx, sloth.TCP, addr)`（v4 的 `Dial` 多返回 `error`）；注入 `option.WithTcpClientHandleMessage` |
| `c_handler.go` | 钩子改为 `handler.TcpClientHandleMessage`（`OnConnect/OnReady/OnData/OnClose/OnError`，签名是 `bucket.IChannel`）。**这是换 TCP 后的必改项**：TCP 无 HTTP 握手，旧的 `*http.Response` 版钩子会被静默忽略，等于"连上了但永远收不到 OnReady" |

## 二、高可用

- **断线自动重连**：`OnClose/OnError` → 重建 `ServerRpc`+`Connect`（v4 拒绝二次 dial 旧对象）→ 指数退避重拨 → 成功后 `services.Rebind()` 回绑新连接。默认开启，`WithDogAutoReconnect(false)` 可关（start/stop/reload 这类一次性命令已关闭）
- **心跳与注册**：README 声称"内置重连+心跳"但代码里只有字段没有实现，现补齐 —— 连上后带重试 `Register`，之后按周期 `Heartbeat`，失败自动重新注册
- `Door.Stop()` 幂等：关监听 + 终止子进程 + 删 PID（不存在视为成功）
- `RegistryStore.Close()`：后台剔除协程此前永不退出，每建一个 store 泄漏一个 goroutine + ticker

## 三、质量缺陷修复

- `startService` 参数传递：`sh -c "cmd" --port X --path Y` 会被 shell 当成 `$0/$1`，业务进程收不到参数 → 改为拼进命令串
- `stopService` 消费 exit 后不清空 `cmd` → **stop 之后再也 start 不起来**，已修
- `runtime.restarts` 在 run 循环与 `enableRestart` 间裸读写（data race）→ 收进加锁方法
- `utils/services`：`sync.Once` 不可重置（重连后无法回绑）；`InitX(nil)` 后 `Cache.Get` 少 nil 检查会 panic；`Use()` 改全局 bucket 无锁 → 统一改为可重绑 holder + `ErrNotInitialized` 哨兵错误 + bucket 读写锁
- `initConfig` 用 `TryFromFiles` 替代会 panic 的 `FromFiles`，并加锁（底层 viper 是进程级单例）
- 库代码里的 `log.Fatalf`/`os.Exit` 全部改为返回 error（`Door.Start/Execute`、root.go）；`WritePID` 错误路径漏关 fd；Windows `Run` 的 ctx 从不 cancel

## 四、验证

- `go vet ./...`：基线 6 条 → **0 条**
- `go test ./... -race`：全绿（新增 6 个测试文件，含 TCP 端到端、Door 重启后 Dog 自动重连、并发控制、goroutine 泄漏、未初始化不 panic）
- 端到端冒烟：Door 监听 TCP → Dog 注册 → 心跳 5s 一次 → 杀掉 Door 后观察到 `[dog] reconnecting in 500ms`
